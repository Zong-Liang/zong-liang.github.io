前端技术栈专题（二）：JavaScript 核心——语言机制、异步编程与浏览器交互

本系列面向具有 Java 后端基础、正在向 React + TypeScript 全栈开发过渡的工程师。本篇系统讲解现代 JavaScript 的语言模型、数据处理、异步机制与浏览器编程，并在末尾通过一个完整的员工管理后台项目串联知识。不设置章节练习、课后题或每日任务，全文只有一个综合实战。

导读：JavaScript 学到什么程度才能进入 React

第一阶段已经讨论了 HTML 的语义、CSS 布局、浏览器渲染与 HTTP。它们决定了页面如何构成、如何显示以及如何与服务器通信。JavaScript 进一步回答另一个问题：用户操作发生后，数据如何变化，浏览器如何根据数据更新页面？

对于习惯 Java 的开发者，JavaScript 最需要重新建立的概念有四个：

  • 值的类型是动态的：变量声明不固定值的类型；对象和数组与 Java 对象一样是引用语义，但比较规则不同：字符串用 === 按值比较；对象没有 equals / hashCode 约定，Map / Set 按对象身份判断键是否相同。
  • 函数是一等值：函数可以存储、传递、返回，并借助词法作用域形成闭包；this 并不是“函数定义所在对象”。
  • 异步不等于并行执行 JavaScript：浏览器在主线程上执行脚本任务，通过事件循环协调任务、微任务和异步 Web API。
  • DOM 是可变的外部环境：JavaScript 既能处理纯数据，也能操作浏览器提供的对象；应尽可能清楚地区分数据逻辑与界面副作用。

本篇采用现代浏览器原生支持的 ECMAScript 模块（ES Modules，简称 ESM）编写示例。此时还不引入 TypeScript、React、npm 或打包工具；它们分别属于后续阶段。

学习完成后应当具备的能力

能够独立阅读常见前端 JavaScript 文件；使用对象、数组和函数组织业务逻辑；解释作用域、闭包、this、异步调用与事件循环；用 fetch 调用 HTTP 资源；在 DOM 中展示和更新数据；处理表单、用户事件、分页筛选、错误和加载状态；并使用 Chrome DevTools 定位行为异常。

第一部分：JavaScript 语言模型

第 1 章 JavaScript、ECMAScript 与运行环境

1.1 JavaScript 语言与 Web API 的边界

通常说“JavaScript 能操作 DOM、发送网络请求”，实际包含两个层次：

  1. ECMAScript：定义语言语法、类型、对象、函数、Promise、模块等核心能力。
  2. 宿主环境：浏览器提供 document、window、fetch、localStorage、计时器等 Web API；Node.js 提供进程、文件、网络服务等另一组能力。
1
2
3
4
5
6

// ECMAScript：不依赖浏览器 DOM
const totals = [12, 20, 8].reduce((sum, value) => sum + value, 0);

// Web API：在浏览器中可用
const title = document.querySelector("h1");
const responsePromise = fetch("./data/employees.json");

这一区分在阅读共享工具函数时很重要。一个仅接收数组并返回结果的函数可以在浏览器、Node.js 或测试运行时复用；一个依赖 document.querySelector() 的函数则需要 DOM 环境。

JavaScript 代码通常在浏览器主线程上执行；浏览器本身仍可以使用其他线程或进程进行网络、渲染与其他任务。Web Worker 能在独立线程执行 JavaScript，但不能直接访问主线程 DOM。

2.4 Number、精度与 NaN

JavaScript 的普通 number 采用 IEEE 754 双精度浮点表示。整数在 Number.MIN_SAFE_INTEGER 到 Number.MAX_SAFE_INTEGER 范围内才能保证安全整数精度。

1
2
3
4

0.1 + 0.2 === 0.3;        // false
Number.isSafeInteger(42);  // true
Number.isNaN(NaN);         // true
NaN === NaN;               // false

涉及金额时，应根据业务的币种、小数精度与运算要求选用整数最小单位、明确的舍入规则或十进制定点库。不能凭一个通用 toFixed(2) 就认为所有金融计算都是正确的；toFixed 返回字符串，而且无法消除输入值的二进制浮点误差。

BigInt 可以表示任意精度整数，但不能直接与 number 混合进行算术运算，原生 JSON.stringify() 也不能直接序列化包含 BigInt 的值（除非应用自定义处理）。

2.7 逻辑运算符、空值合并与可选链

|| 和 && 返回参与运算的操作数，而不是始终返回布尔值。?? 只在左侧为 null 或 undefined 时采用右侧默认值。

1
2
3
4

const employee = { profile: null };

可选链 ?. 只防止其直接检查的位置为 null / undefined；它不会吞掉函数内部异常。obj.missing?.() 在方法不存在（值为 null / undefined）时返回 undefined；但如果属性存在而不是函数，例如 obj.count?.() 中 count 为数字，仍会抛出 TypeError。无意中把真实异常隐藏成默认值，会增加问题定位成本。

3.1 函数声明、函数表达式和箭头函数

8.1 同步执行为什么会阻塞页面

JavaScript 在主线程执行同步代码时，一段长时间不返回的计算会阻碍同一线程继续处理点击、绘制协调等工作。

1
2
3
4

  // 同步计算，循环结束之前当前调用栈不会退出
}
console.log("结束");

浏览器的异步能力并不意味着任意 JavaScript 函数能自动被多个线程并行执行。把耗时计算写进 async function 但不主动让出执行，也不会神奇地让它在后台线程运行。

8.2 调用栈与宿主事件循环

函数执行时进入调用栈，返回时出栈。浏览器运行环境在事件循环中处理任务，例如定时器回调、用户事件等，并在适当的微任务检查点执行微任务。具体任务来源和调度时机由 HTML 规范与浏览器实现共同决定。

基本理解模型：当前同步执行完成后，先清空已排队的微任务，再进入后续任务；渲染可能在合适的事件循环阶段进行，而不是每条语句之后都发生一次。

在常见浏览器主线程执行环境中，输出顺序是：A → E → C → D → B。理由：A、E 是当前同步任务；C、D 是按顺序排队的微任务；B 是后续任务。setTimeout(fn, 0) 不保证立即执行，也不保证严格在 0 毫秒后执行。

8.4 微任务不是越多越好

如果一个微任务不断添加新的微任务，浏览器可能长时间无法进入下一任务及渲染机会，形成微任务饥饿。不应利用海量 queueMicrotask() 代替正常的任务调度。

8.5 setTimeout()、setInterval() 与 requestAnimationFrame()

  • setTimeout(fn, delay)：最早可执行时间受到延迟、浏览器节流和任务调度影响，不适合作严格计时保证。
  • setInterval(fn, delay)：间隔触发；执行时间和事件循环繁忙程度会造成偏差。
  • requestAnimationFrame(fn)：用于在浏览器准备下一帧时安排动画更新，适合与视觉变化协调；后台标签页可能暂停或降低调用频率。

对于输入查询，通常用防抖减少短时间高频触发；对于滚动或尺寸变化可根据场景采用节流、requestAnimationFrame 或专用观察器 API，不必所有事件都盲目做节流。

第 9 章 Promise 与 async / await

9.1 为什么需要 Promise

网络请求、文件读取或等待计时器结束都可能在未来才产生结果。Promise 表示一个异步操作最终结果的状态，而不是把 JavaScript 主线程阻塞在原地等待。

Promise 存在三类状态：

  • pending：尚未完成。
  • fulfilled：已成功完成，携带一个结果值。
  • rejected：失败，携带拒绝原因。

fulfilled 与 rejected 统称已敲定（settled）。Promise 一旦敲定，最终状态不可再次改变。需要特别注意：被 resolve 为另一个 Promise 时，可能仍处于 pending，直到采用的 Promise 完成。

async 函数调用总是返回 Promise。await 暂停的是当前 async 函数的继续执行，不会阻塞主线程。await 后续代码一般作为微任务继续执行；如果 Promise 拒绝，对应位置表现为抛异常，可用 try/catch 捕获。

await 可以用在 async 函数内，也可以用于支持它的模块顶层。顶层 await 会影响模块图的求值时机，因此应当审慎使用。

API完成条件主要用途
Promise.all()全部成功；出现拒绝则聚合拒绝必须全部成功的独立请求

Promise.race()第一个敲定的结果竞争多个 Promise
Promise.any()第一个成功；全部失败时拒绝多来源中任一成功即可

10.7 Cookie、凭证和跨域

不要在客户端源代码中硬编码敏感令牌或密钥。浏览器中的代码及发出的请求对用户可见；身份认证和授权检查应由后端负责。

防抖（debounce）：事件持续触发时推迟执行，直到停止触发达到指定时间。适用于搜索框停止输入后触发查询。

  return (...args) => {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn(...args), delay);

function throttle(fn, interval) {
  let lastRun = -Infinity;
  return (...args) => {
    const now = performance.now();
    if (now - lastRun >= interval) {
      lastRun = now;
      fn(...args);
    }
  };
}

以上是便于学习的基础版本，尚未处理 this 保留、尾部调用、立即取消、异常传播等完整库级语义。生产代码可复用成熟工具或根据需求设计完整实现。

第 13 章 调试方法、可维护性与安全边界

13.1 Console 是起点，不是完整调试器

console.log() 能快速观察值；console.table() 适合检查数组对象；console.error() 有助于归类错误。但对于需要追踪事件传播、Promise 结果或中间状态变化的场景，逐步断点通常更可靠。

1

不要在生产环境记录认证令牌、手机号、身份证号、敏感响应体等信息；调试效率不应以数据泄露为代价。

13.2 Sources：断点、调用栈、作用域和 Watch

定位一个“按钮没响应”的问题，可以按以下链路检查：

  1. 在 Elements 中确认按钮实际存在，且未被 disabled 或覆盖层阻碍。
  2. 在 Sources 的监听器入口设置断点，确认事件能否进入。
  3. 检查 Call Stack，确认调用路径。
  4. 在 Scope / Watch 中检查 event.target、当前筛选条件和数据集合。
  5. 单步执行直到实际状态更新或 DOM 渲染的位置。

对于异步函数，关注 await 前后状态以及网络响应何时返回，不应仅凭日志的视觉排列推断全部因果。

13.3 Network：不仅看状态码

至少检查：请求 URL 和查询参数、请求方法、请求头、响应头、Status、Preview/Response、Timing、是否命中缓存。fetch 返回 200 并不保证业务数据结构正确；后端的 JSON 响应可能是 {code, message, data}，也可能是一个直接数组，必须按接口契约解析。

在本篇综合实战中，employees.json 是静态文件，Network 应看到正常的 GET 请求。如果直接使用 file://，出现跨源模块报错属于运行方式问题，不应通过关闭浏览器安全机制来规避。

13.4 性能：先测量再优化

前端性能涉及 JavaScript 执行耗时、DOM 大小、样式与布局计算、绘制以及网络。不要一开始就将每个函数包裹在缓存层中。对于列表操作，应先确认数据规模与用户可感知的性能问题；小数据量使用清晰的数组转换更容易维护。

确实存在性能问题时，再通过 Performance 面板或性能指标，判断瓶颈位于脚本、布局、渲染、资源加载还是网络。

13.6 安全模型中的职责分界

  • 前端对输入做格式校验，提升交互体验；后端仍需独立校验和鉴权。
  • 直接插入用户输入到 HTML、脚本或 URL 的危险上下文可能导致 XSS；应按数据用途选择安全 API。
  • CORS 决定浏览器是否允许跨源读取响应，并不是后端的授权系统，也不能代替鉴权。
  • 浏览器中任何被下载的前端 JavaScript 都可被用户查看；前端常量和构建环境变量不是保存服务端秘密的地方。
  • 客户端上的“删除成功”可能只意味着本地状态变化；必须有服务端确认才能称为真实业务持久化成功。

export function queryEmployees(employees, filters, page, pageSize = 5) {
  const normalizedKeyword = filters.keyword.trim().toLocaleLowerCase("zh-CN");

  const filtered = employees.filter((item) => {
    const nameMatches = item.name
      .toLocaleLowerCase("zh-CN")
      .includes(normalizedKeyword);
    const departmentMatches = !filters.department || item.department === filters.department;
    const statusMatches = !filters.status || item.status === filters.status;
    return nameMatches && departmentMatches && statusMatches;
  });

  const sorted = [...filtered].sort((a, b) => {
    if (filters.sort === "name-asc") return nameCollator.compare(a.name, b.name);
    const idOrder = Number(a.id) - Number(b.id);
    return filters.sort === "id-desc" ? -idOrder : idOrder;
  });

  const pageCount = Math.max(1, Math.ceil(sorted.length / pageSize));
  const currentPage = Math.min(Math.max(1, page), pageCount);
  const start = (currentPage - 1) * pageSize;

  return {
    records: sorted.slice(start, start + pageSize),
    total: sorted.length,
    currentPage,
    pageCount,
  };
}

这段函数依赖 model.js 顶部初始化的 nameCollator = new Intl.Collator("zh-CN")，完整定义见源码。关键顺序是：先筛选，再排序，最后分页。如果先分页再筛选，用户可能在第 2 页搜不到实际存在于第 1 页的记录；如果不进行页码校正，删除最后一页唯一员工后可能显示错误页码。

sort 总是对数字大小排序默认按转换后的字符串比较
this 总指向函数定义的对象普通函数按调用形式决定；箭头函数使用外层 this
async 自动在新线程运行async 返回 Promise，不会自动创建 JavaScript 执行线程
await 阻塞整个浏览器线程暂停当前异步函数的后续执行，不阻塞整个主线程
Promise.all 失败会取消其他请求聚合结果拒绝，其他已启动请求通常继续执行
fetch 收到 404 会进入 catch正常返回 Response，需要检查 response.ok
textContent 与 innerHTML 只是写法不同前者显示纯文本，后者解析 HTML，安全语义不同
localStorage 等同数据库它是浏览器端、同步、受限的本地存储，不承担后端持久化职责
浏览器能请求成功就不需要校验HTTP 状态、响应格式、业务字段和后端授权都需要分别考虑
