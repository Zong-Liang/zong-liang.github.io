Writecraft：让 AI 写作先解决内容问题，再处理表达

AI 已经能把一段话写得很通顺，但通顺不等于写得好。

写一篇分析文章时，可能罗列了大量观点，却没有充分的依据；整理一份报告时，章节看起来完整，却没有回答真正的问题；修改已有文稿时，语言变得更加“专业”，原本的判断和限定条件反而被改变。

还有一种常见情况：明明只是要求润色几句话，AI 却重新生成了一整篇文章。标题、列表和总结样样齐全，但读起来仍然像一份套用模板的内容。

这些问题并不完全属于语言表达。

写作首先需要明确要解决什么问题、现有材料能支持什么结论、读者需要知道哪些信息，以及如何组织这些信息。表达是其中重要的一环，但不是全部。

基于这些考虑，我开发了 Writecraft，一个面向 AI 助手的内容构建与专业写作 Skill。

它希望解决的不是“怎样让 AI 写得更多”，而是“怎样让 AI 更准确地理解和完成写作任务”。

Writecraft 是什么？

Writecraft 是一个内容构建与专业写作 Skill，适用于从零创作、材料整理、结构重组、内容审查，以及已有文本的润色、改写、翻译和总结。

它支持中文、英文和双语内容，可以用于技术方案、调研报告、研究摘要、工作汇报、博客文章、邮件等场景。

与单纯关注语言表达的提示词不同，Writecraft 把写作看作一个需要综合判断的任务。

面对一个写作请求，它需要先理解用户想完成什么、内容面向谁、现有材料提供了什么，再决定如何处理。

例如，用户希望根据访谈记录撰写一份产品改进建议，任务就不只是把访谈内容整理得通顺，而是需要区分用户实际反馈了什么、这些反馈能支持哪些判断、哪些改进建议仍然需要验证。

但如果用户只是要求润色其中一段话，Writecraft 不应该擅自修改观点、重组全文或补充未经确认的事实。

不同的写作任务需要不同的处理深度，而不是统一套用一套写作流程。

Writecraft 主要解决什么问题？

1. 内容完整，却没有回答真正的问题

AI 很擅长生成结构完整的文章。

例如，要求它撰写一份用户满意度调查分析报告，常见的输出可能包含调查背景、问卷说明、结果统计、问题分析和改进建议。

这些内容未必错误，但如果报告的目的是决定下一阶段应该优先改善哪些体验，仅仅按照问卷题目罗列统计结果还不够。

读者真正关心的可能是：

  • 哪些问题最集中，影响了哪些用户？
  • 不同用户群体的反馈是否存在明显差异？
  • 哪些结论有调查数据支持，哪些只是可能的解释？
  • 哪些问题值得优先处理，判断依据是什么？
  • 后续需要补充哪些信息才能作出决策？

Writecraft 强调从写作目的出发，把宽泛主题转化为需要回答的问题，再组织主张、依据和必要的限定条件。

它不会仅仅因为一份文档拥有完整的章节，就认为内容已经充分。

2. 结构清晰，但读起来仍然费力

结构化表达很重要，但并不意味着每篇文章都应该使用相同的组织方式。

解释一个概念与支持一项决策，需要不同的论述顺序；面向初学者的学习文章与面向专业人员的操作手册，也不应该具有相同的信息组织方式。

例如，介绍一套新的协作工具，如果读者此前从未接触过它，可以先说明它解决什么问题，再解释主要功能及基本使用方法。

但如果读者已经熟悉工具，只想解决某个具体操作问题，那么直接给出操作前提、处理步骤和检查方法通常更加有效。

Writecraft 根据读者已有的知识和阅读目的组织内容：

先解释后文依赖的概念，把关键条件放在相关结论附近，使用实例帮助理解抽象机制，并在确有需要时采用流程图、表格或分步说明。

同时，它避免为了结构化而结构化。

一段简单说明不必拆成多个章节，一封简短邮件也不需要机械地添加背景、目标、措施和总结。

好的结构应该降低理解成本，而不是增加阅读负担。

3. 语言更流畅，却改变了原意

AI 编辑现有文本时，容易出现另一类问题：语言得到优化，信息却发生偏移。

例如，假设原文是：

在本次访谈中，部分参与者表示，新版操作流程比之前更容易理解。

不恰当的改写：

新版操作流程显著改善了用户体验，获得了用户的广泛认可。

两句话看起来表达相近，但后者将部分参与者的主观反馈扩大成了整体结论，还引入了原文没有提供依据的效果判断。

Writecraft 要求在修改已有文本时，保留作者的立场、事实、数字、专业术语及结论适用的条件。

校对、润色、改写和重写也具有不同的修改范围。

如果只是润色，应优先解决局部措辞和衔接问题；如果需要结构重组，则可以调整论述顺序、合并重复内容，但不能随意改变作者原本的判断。

有些句子本身已经准确、自然，并不需要为了体现修改效果而强行改动。

4. “去 AI 味”变成另一种机械改写

所谓“AI 味”，通常不是某几个词语造成的，而是内容和表达共同作用的结果。

比如，缺少依据的评价、重复出现的抽象判断、刻意对称的章节标题、与实际内容无关的过渡句，以及没有提供新信息的结尾总结。

如果只是禁止一些常见词语，再换用另一组表达，文章未必会更好。

Writecraft 对“去 AI 味”的处理不依赖固定禁词表，而是判断具体问题：

这句话是否提供了实际信息？这个标题是否准确概括内容？这里的总结是否必要？这段表达是否符合文稿的用途？

能通过补充事实、解释机制或调整结构解决的问题，不应简单地归结为措辞问题。

Writecraft 如何工作？

Writecraft 没有要求所有任务严格执行相同的写作步骤，而是根据任务性质选择处理方式。

从零写作时，重点在于明确问题、组织材料、建立论述关系，形成能够支持结论的正文。

修改已有文稿时，重点在于识别实际问题，在授权范围内调整结构或表达，并对照原文检查是否发生信息损失。

审查文稿时，重点不在于直接重新生成文章，而是指出具体问题、解释原因，提供可执行的修改建议。

这些处理方式遵循一些共同原则。

准确性优先于表达效果。 区分事实、作者观点、推断和假设，不用流畅的语言掩盖证据不足，也不在缺少依据时擅自扩大结论。

内容组织服务于读者理解。 根据读者的知识基础安排解释顺序，确保必要的前置概念、条件和证据能够在合适的位置出现。

修改范围由任务决定。 用户要求什么，就优先完成什么。发现额外问题时，可以指出，但不代表获得了修改全文的授权。

表达应符合实际文体。 研究报告注重依据和限定条件，工作汇报需要交代动作、状态与结果，博客文章可以更自然地展开论述，而简短消息通常不需要复杂的章节结构。

这些原则并不保证每次生成的内容都完全正确。涉及外部事实、实验结果或技术版本时，仍需要具备相应的材料、核实手段和人工判断。

如何使用 Writecraft？

Writecraft 不要求用户学习一套复杂的写作命令。

安装后，直接描述写作需求，并提供相关材料即可。

例如：

从零创作

我想写一篇关于远程办公如何影响团队协作的文章，面向普通职场读者。请帮我梳理值得讨论的问题，区分已知事实与个人观点，再组织成一篇逻辑清楚、语言自然的文章。

整理零散材料

这是几次会议的记录和一些补充说明。请整理成一份项目进展报告，区分已经完成的工作、当前存在的问题和下一步计划，不要把尚未确定的事项写成最终决定。

重组文档结构

这份年度工作总结的内容基本完整，但章节之间有重复，重点也不够突出。请检查内容关系，必要时调整结构，保留原有事实和成果，不要增加未经确认的数据。

润色与去 AI 味

帮我润色这篇博客文章，主要解决空泛表达、机械过渡和不自然的句子。保持原有观点和个人写作风格，不需要重写全文。

翻译与双语表达

将这段英文研究摘要翻译成中文，保留专业术语、原文的推断程度和研究条件。要求符合中文学术表达习惯，不要自行强化结论。

内容审查

帮我审查这篇分析文章，重点检查观点是否有依据、论证是否连贯、是否存在以偏概全的问题，以及哪些地方可能让读者难以理解。先指出具体问题和修改建议，不要直接重写。

使用时，越明确的任务目的、目标读者和已有材料，通常越有助于获得符合实际需求的结果。但不需要提前设计好文章的全部结构。

当用户只有一个主题或者一些零散想法时，Writecraft 也可以协助梳理问题、组织材料并形成初稿。

安装

Writecraft 目前提供 Codex Skill 和 Claude Code Skill／插件的使用方式。

Codex

可以在 Codex 对话中使用 Skill Installer：

1

$skill-installer 从 https://github.com/Zong-Liang/writecraft/tree/main/skills/writecraft 安装 Writecraft

也可以将仓库中的 skills/writecraft/ 目录复制到：

1

~/.agents/skills/

Claude Code

下载仓库后，可以通过本地插件市场安装：

1
2

/plugin marketplace add /path/to/writecraft
/plugin install writecraft@writecraft

其中 /path/to/writecraft 需要替换为实际的仓库目录。

也可以将 skills/writecraft/ 复制到：

1

~/.claude/skills/

写在最后

Writecraft 最初关注的是一个很实际的问题：为什么 AI 已经能够生成流畅、完整的文章，我们仍然需要花费大量时间修改它？

原因之一是，写作质量并不只取决于语言是否自然。

对于专业内容，问题是否明确、事实是否准确、判断是否有依据、论述是否合理、读者是否能够理解，往往比辞藻更重要。

Writecraft 尝试将这些要求融入 AI 的写作过程，让内容构建与语言编辑相互配合，而不是把写作简单等同于生成文本。

它并不试图规定一种统一的“好文章”格式，而是希望 AI 能够根据任务、材料和读者，做出更合适的内容与表达选择。
